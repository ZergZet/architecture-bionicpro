
# Задание 1. Повышение безопасности системы

## Задача 1. Архитектурное решение для управления учётными данными пользователя. 

Решение должно учитывать и обеспечивать следующие аспекты:
- Унификацию доступа в системе BionicPRO. Это будет осуществляться через запрос данных учётных записей из внешнего источника, который расположен в стране представительства компании. Принципы локального хранения персональной и медицинской информации не должны быть нарушены.
    - Добавлен Keycloak
    - База пользователей и ролей (без медицинских данных)
    - Добавлен внешний IdP страны представительства

- Безопасную схему работы с access- и refresh-токенами, которая исключает передачу фронтенду токенов, которые были получены от IdP.
    - так как предполагается использвование только мобильного приложения, то нет необходимости в BFF 
     1. Мобильное приложение делает всё по потоку PKCE напрямую с Keycloak. 
     2. Получает access_token и refresh_token. 
     3. Хранит их в защищённом хранилище ОС (Keychain на iOS, EncryptedSharedPreferences на Android). 
     4. При каждом запросе к API приложение прикладывает access_token. 
     5. Если токен истёк — приложение само тихо запрашивает новый через refresh_token.     
    - Плюсы: 
     1. Проще архитектура. Меньше компонентов, меньше кода, меньше точек отказа. 
         - Авторизация через системный браузер при перенаправлении пользователя из приложения на страницу Keycloak хоть и не даёт приложению видеть пароль, но при этом как раз браузер подвержен большему числу различных атак, нежели специализированное приложение. 
     2. Меньше задержек. Запрос идёт напрямую от клиента к API-сервису, минуя лишний прокси. 
    - Почему это безопасно:
     1. Нет client_secret в коде приложения благодаря PKCE. 
     2. Токены хранятся в защищённых хранилищах Keychain/EncryptedPrefs. 
     3. Современные мобильные ОС (iOS/Android) дают очень хорошую изоляцию приложений.
     3. Даже если устройство с приложением скомпрометировано, злоумышленник получит токен, срок жизни которого ограничен (например, 15 минут).

- Для возможность поддержки аутентификации пользователей через различные внешние удостоверяющие службы, действующие в разных странах.
    - добавлен внешний IdP подключённой страны

## Задача 2. Улучшение безопасности существующего приложения, заменой Code Grant на Authorization Code Flow + PKCE:

 - в Keycloak для public-клиента reports-frontend включается standardFlowEnabled, отключаются implicit и direct access grants, задаётся PKCE S256;

 - во фронтенде keycloak-js инициализируется с flow: 'standard' и pkceMethod: 'S256'.
